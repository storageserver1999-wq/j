# Propeller Engine

Propeller Engine is a WebGPU-based scene editor built with Three.js, TypeScript, and Vite.

## Run locally

```sh
npm install
npm run dev
```

Open the local URL printed by Vite in a WebGPU-capable browser.

Hold the left mouse button and drag to orbit the scene. Hold the middle mouse button and drag a box to select multiple blocks; use the Move, Rotate, or Scale tool to transform them together, and use Configurations to change their shared Model and Chromatics settings. Multi-block transforms pivot on the middle of the combined selection bounds, so Move drags the group by that centre and Rotate/Scale turn and grow it around the same point; selecting via the box keeps nested blocks rigid, with parents applied before their children. Rotate and Scale handles follow each object's own orientation, while Move stays world-aligned. Press **`** to toggle free camera; hold the right mouse button to look around. **W/S** move forward and backward in the direction you are looking, **A/D** strafe, and **Space/C** move vertically. The transform gizmo stays active in free camera, so an object can still be moved, rotated or scaled with the left mouse button while flying; the fly keys only respond to a bare press, so **Ctrl+C** still clones the selected object instead of being read as “C = descend”. The camera keeps its position when free camera is turned off. **Ctrl+Z** steps one transform edit back and **Ctrl+X** steps it forward again; **Ctrl+C** still clones the selected object. A right click in the viewport is inert — object actions live on the Scene Explorer row's context menu.

## Scene tools

Use **Shapes** in Scene Explorer to add models — including a flat **Image Block**, a two-triangle picture plane that shows one fitted copy of a PNG, JPEG, WebP, or AVIF chosen in its **Texture** section (or dragged from the PBR workspace). Transparent PNG pixels are cut out rather than drawn on an opaque rectangle, and the God Rays occlusion mask uses the same alpha test, so a picture with transparency blocks the sun with its silhouette instead of a full plane — or **Insert** to add a **Spot Light**, **Universal Light (Sun)**, **Point Light**, **God Rays**, **Shadows**, **Atmosphere**, **Monitor**, or a **World Skybox** — all directly in the menu, with a search field at the top that filters the list as you type. Enabling **God Rays** creates a God Rays effect child of the sun (adding a Universal Light if the scene has none) and exposes a **Quality** tier (Low/Medium/High = 16/32/64 march taps into a 40/55/100%-resolution buffer) plus intensity, spread, decay, brightness, and tint controls in the sun's Configurations. The effect renders the scene as a white-sky/black-occluder visibility mask, marches TSL taps from each pixel toward the projected 3D sun, and carves the shafts out of the geometry silhouettes, so light stays locked to the sun while foreground blocks it. The march renders into its own reduced-resolution buffer and does not run at all while the sun is behind the camera or out of frame, which keeps the pass off the frame budget at high resolutions. Set a skybox to a cube or sphere. Cube skyboxes have editable width, height, and depth, and can use separate face images or one image applied to all six sides. You can also import a PNG, JPEG, WebP, or AVIF 4×3 cross atlas in the reference or standard cubemap layout. Sphere skyboxes accept one image. Image previews appear beside the image controls; removing an image restores the previous face color. Color controls are hidden while an image is assigned. Skyboxes are configured with these controls rather than transform gizmos. Newly added lights start at brightness 2, focused spot/point beams cast shadows by default, and their direction arrows track the aimed beam. The sun's **Cast Shadow** is off by default. When it is on, the directional light is moved to a short distance along the sun's direction (the marker still sits 40 000 units out) and its orthographic shadow camera is re-fitted every frame to the world-space bounding sphere of everything that casts or receives a shadow. That keeps blocks outside the old fixed square shadowed, keeps the map sharp when a floor is stretched, and — because the light now sits near the scene instead of tens of thousands of units away — gives the depth comparison enough precision that flat triangulated surfaces no longer break into acne stripes. Bias and normal bias follow the fitted texel size, so the shadow stays stable while the scene is edited. Switching Cast Shadow off no longer clears `castShadow`: on that transition three disposes the light's shadow render target while every compiled material keeps the destroyed texture bound, which logged WebGPU "destroyed texture" errors and could throw inside the shadow update and stop the render loop — the toggle now zeroes `shadow.intensity` and freezes the map instead, so shadows switch off and on instantly in both directions. **Insert → Atmosphere** adds a scene-wide **Atmosphere** row: sky-colour and ground-colour ambient light with an intensity, viewport **Exposure**, environment intensity, and exponential fog colour/density. **Insert → Monitor** adds a **Monitor** row that renders the preview into a smaller buffer (Native, 420p–1440p) and scales it to the panel, which lowers the cost of the scene, the god rays and the reflection probe together; the panel reports the live buffer size. Its **Exclude viewport** switch keeps the 3D view at full resolution while the setting stays saved, for when a low preview resolution would make editing hard.

**Insert → Shadows** adds a scene-wide **Shadows** row to Scene Explorer; its Configurations control **Enabled**, **Shadow color** (the colour a surface keeps where a shadow falls — black by default, so picking a colour tints the shadows), **Resolution** (512–4096), **Blocky shadows** (hard, unfiltered edges instead of smooth PCF), **Strength** and **Softness**. The settings are applied to every shadow-casting light, including lights added afterwards, and removing the row restores the engine defaults. The sun has a size control for its visible marker and glow; the glow is an additive shell shaded by three radial falloffs (a bright core, a soft bloom and a very wide wash) so it reads as a faint halo instead of a flat pale disc, and it is purely cosmetic — the shafts are screen-space and stay locked to the sun's projected position regardless of how the marker is shaded. **View → Preferences** opens a movable, resizable settings window with Rendering, Configurations, and UHD UI-color options. **Lighting technology** switches between **Mlight**, the plain rasterized renderer, and **Mlight RT**, which adds screen-space ray-traced light occlusion for directional, spot, and point lights with Low, Medium, and High quality tiers (1/2/3 traced lights and 10/20/32 depth samples). It only traces lights whose **Cast Shadow** is on, so the per-light toggle controls the traced shadow as well as the shadow map. WebGPU exposes no hardware ray tracing, so the pass walks the depth buffer instead of a BVH and is an approximation. Preferences remember window placement, UI colors, and automatic Model/Chromatics expansion settings. The top-bar **Sculpting** button is reserved for a future tool.

**Model** keeps its Faces control usable down to each shape's low-poly base mesh, so spheres, pills, toruses, and cylinders are no longer held at a high triangle minimum (80, 60, 64, and 32 triangles respectively) while new objects still start smooth. Smooth shading now averages only the faces that actually share a surface: cubes keep crisp flat faces and 90° corners, cylinders keep a round barrel with hard rims, and spheres, pills and toruses stay fully smooth. Before, every coincident corner vertex was averaged with all the faces meeting there, so a flat cube side shaded as a rounded gradient and its shadow bias was pushed in the wrong direction. **Chromatics** ends with **Reflectance** (metalness plus gloss) and **Transparency** (opacity) bars, each with ◀ ▶ steppers, a filled track, and a numeric readout that stays in sync with the Material presets. A live reflection probe captures the scene into a pre-filtered environment map from the camera, so a high **Reflectance** surface mirrors the skybox, the grid and the surrounding blocks; mirror surfaces are hidden and the studio environment is swapped back in while capturing, so neither a sphere's own image nor the probe's previous output can feed back into the next capture (that loop is what used to turn a closed room into a glowing white box). It recaptures every 150 ms while the view moves but only every 2 s when the view is still, and at a 128-pixel cube size: one capture renders the scene into six cube faces inside a single frame, so re-capturing a motionless scene every 150 ms was the source of the periodic hitch. Reflections come from the probe plus the material response; the screen-space reflection node shipped with this three build produced an invalid render pipeline on WebGPU, so it was removed rather than submitting a broken pass every frame (only the probe's contribution was ever visible). A procedural sky tone keeps reflections readable in an otherwise black scene. The viewport grid is two-sided, so it stays visible when the camera moves below it. **View → Grid distance** sets how far it reaches, from 5 m up to 250 m; the sub-metre lines fade out with view distance so a large grid stays clean out to the horizon. A 3D orientation gizmo sits in the top-right corner of the viewport: it tumbles with the camera, clicking an axis sphere glides the camera to that side of the scene, and clicking the centre dot eases back to the view the editor opened with. While editing points, left-dragging empty space still orbits the view; a click without a drag clears the point selection.

**Insert → Import 3D Model…** (also in the PBR workspace's **+** menu) brings a glTF/GLB, OBJ, FBX, STL, PLY, 3DS, or DAE file into the scene. The picker accepts several files: the model plus its `.mtl`, `.bin`, and texture images, which the loader resolves by file name, so OBJ/DAE/FBX files that reference external pictures still show their maps (glTF/GLB, FBX and 3DS textures embedded in the file work on their own). FBX and OBJ files whose maps are TGA are supported too (embedded TGA in FBX and external `.tga` next to an OBJ/FBX); PNG, JPEG, WebP and AVIF work everywhere. Every mesh is baked into world space and merged into one block with no triangle budget, but its materials are kept as material groups, so an imported tree shows its bark and leaf textures instead of a flat grey. The importer waits for the asynchronous image loads of FBX, DAE, and 3DS before converting those materials, so their maps are already attached instead of importing as flat colours. Foliage is cut out from the base-colour map's own alpha instead of a separate alpha mask, which keeps a tree visible even when its mask-only texture cannot be read, and a file baked through a mirrored transform has its winding and normals corrected so it is not culled away. The result is a normal scene object — Move/Rotate/Scale, **Ctrl+C**, shadows, and the god-ray occlusion pass all work on it, and its clone keeps the materials, texture maps, flags and file tree. Scene Explorer shows the file's own contents under the object with nested **›** disclosures: nodes can contain meshes, meshes contain materials, and materials contain texture maps, as deep as the file goes; a map whose external picture was not picked reads **missing image**, which points at the fix (import again with the images). Configurations keeps the name, transform readouts and a **Texture** section: it reports **File texture** when the file brought its own maps, dragging a PBR ball onto its square replaces them on every material group while keeping the file's authored UVs, and **Clear texture** restores the file's own maps. Model and Chromatics stay hidden for these blocks.

Scene Explorer draws Godot-style hierarchy connectors: a trunk runs down the left of a group's children and each child meets it with a rounded elbow, with the trunk stopping at the last child. Drag one model onto another in Scene Explorer to parent it. Child blocks move with their parent but remain individually editable. Right-click a parent to group nested blocks, combine its child blocks into one model, or **Ungroup all blocks**: that releases every descendant to the scene with its world transform kept, including a child that has children of its own, and on a lone child it simply unparents the block. A parent with children also gets an **Apply to all blocks** option in Chromatics. With an object selected, **Ctrl+C** clones it without changing the system clipboard; **Ctrl+V** remains the normal paste shortcut.

## Textures

**PBR WORKSPACE** under the viewport is a material browser: one circular card per texture, each showing the whole texture on a lit sphere with its name underneath, laid out in a grid that reflows and scrolls as you add more or resize the dock. Its **+** menu (**Add texture…** for a PNG, JPEG, WebP, or AVIF, plus **Checkerboard** and a blueprint **UV grid**) adds a card. Both presets are drawn procedurally at 1024 px; the UV grid is a slate checkerboard whose tiles each carry a fine sub-grid and a brighter boundary line. The preview canvas is a fixed overlay on the visible workspace, and each visible card is clipped to that rectangle with an off-center camera projection, so a half-scrolled card keeps its ball lined up and nothing is drawn outside the panel; the preview redraws when the dock is resized or scrolled. Cards shrink with the dock — below a certain height their names are hidden first — so a short workspace shows a smaller sphere instead of cropping it, and a card that is only partly scrolled into view draws nothing rather than a sphere sliced flat at the panel edge. The header **×** hides the whole dock; **View → PBR → PBR workspace** brings the same instance back at its former height with every texture, tab and assignment intact. **Right-hold a ball and drag to turn it** and inspect the texture; the pointer is captured and the cursor hides for the turn, and releasing — even outside the dock or after an alt-tab — always ends it. Every card is drawn by clipping one shared WebGPU view to the card, so a grid of thumbnails costs a single pass.

Clicking a ball opens its browser-style tab above the workspace, with the picture as the tab icon and an **×** to close it; closing a tab keeps the ball, and clicking the ball brings the tab back. The workspace draws only when something changes, so an idle dock costs no GPU time.

With an object selected, **Configurations → Texture** ends with a square drop target: left-drag a ball onto it to apply that texture to the object, and **Clear texture** removes it (restoring the colour the surface had before). Generated geometry now carries its own UVs. When a texture is applied they are re-projected into object space divided by the object's world scale (a box projection on cubes and joined models, a spherical one on the other shapes), so one image tile covers one metre of surface: stretch or scale a block and the pattern tiles more often instead of stretching with it. The UVs are refreshed while the gizmo scales the object, and a cloned object keeps its texture assignment and retiling, so stretching the copy tiles the picture instead of smearing it. The Texture section's **Disable all textures** switch hides every applied map at once (the assignments are kept, so turning it back on restores them), including the per-material maps an imported file brought with it. On a textured surface **Reflectance** only adds a light sheen and a hint of the sun rather than turning the object into a mirror, because a fully metallic surface would drop the picture entirely.

## Build

```sh
npm run build
```

The Electron desktop wrapper can be started with `npm run desktop`.

On Windows, `npm run package:win` creates an installer (with Start menu and desktop shortcuts) and a portable executable in `release/`. The browser build is the `dist/` folder; serve it over HTTP with `npm run preview` rather than opening `index.html` directly.
